## Что хранится в директории и как запускать?

Репозиторий содержит ноутбуки с исследованием и артефакты, которые они сохраняют. Воспроизведение идёт в линейном порядке.

### Ноутбуки

- `00-eda.ipynb` — разведочный анализ данных: обрезка по дате, выбор ширины окон валидации и теста, распределения пользователей и контента, анализ холодного старта, формулировка плана feature engineering.
- `01-preprocessing-and-sampling.ipynb` — построение ручных признаков для айтемов и пользователей, генерация негативных примеров (1:2), сборка `train_final`, KNN-ретривер для формирования пула кандидатов, стратифицированные семплы пользователей для train/val и сохранение артефактов.
- `02-baseline-training.ipynb` — обучение CatBoost на полном наборе ручных признаков (сильный baseline) и его оценка на отложенных выборках.
- `03-two-tower.ipynb` — обучение двубашенной модели с контрастивным лоссом, извлечение эмбеддингов, оценка как рекомендера через dot product.
- `04-raw-features-catboost.ipynb` — контрольный CatBoost на восьми сырых признаках без feature engineering.
- `05-vae-embeddings.ipynb` — обучение гибридного VAE (user + item) и CatBoost на VAE-эмбеддингах совместно с ручными агрегатами.
- `06-final-evaluation.ipynb` — единая финальная оценка всех четырёх моделей на train/val/test с разбивкой на холодных и тёплых пользователей, выгрузка итоговой таблицы.

## О чём исследование

Рекомендательные системы определяют, какой контент видят и какие товары выбирают миллионы людей. Значительная часть их качества обеспечивается признаками, которые инженеры проектируют вручную: агрегаты по истории, скользящие окна, отношения между сущностями. В смежных задачах машинного обучения (например, классификации текстов) ручные признаки давно вытеснены нейросетевыми моделями, которые извлекают закономерности из данных автоматически. В рекомендательных системах ручной feature engineering по-прежнему остаётся надёжным способом получить высокое качество.

Задача исследования — проверить на реальном датасете, можно ли заменить или дополнить ручной feature engineering обучаемыми представлениями без потери качества рекомендаций. Градиентный бустинг на сильном наборе ручных признаков выступает нижней планкой, которую альтернативные подходы должны догнать. Победа над бустингом не была обязательной целью: хорошо поставленный отрицательный эксперимент с анализом причин также считается валидным результатом.

Работа проводилась на датасете KION (МТС) — лог взаимодействий пользователей с фильмами и сериалами. Из-за ограниченных вычислительных ресурсов (лимит GPU на Kaggle, сжатые сроки) не все экспериментальные ветки удалось довести до полного цикла, а для финальной оценки использовались уменьшенные стратифицированные выборки пользователей. При этом соблюдалось важное условие: сравниваемые модели обучались и валидировались на одном и том же временном split, на одном и том же пуле кандидатов и на одном и том же распределении холодных и тёплых пользователей. Обучение велось на максимально свежих данных, оценка — на семплах, распределения которых совпадали с генеральной выборкой.

**Ключевые выводы:**
- Задача исследования — корректно проверить, конкурируют ли обучаемые представления с ручным FE.
- Все модели сравниваются при одинаковых условиях (split, кандидаты, стратификация по cold/warm).
- Ограниченность ресурсов решалась через стратифицированные выборки для финальной оценки, а не через урезание истории пользователей.

### 2.7. План feature engineering

По итогам анализа сформулированы следующие преобразования (совпадают с тем, что реализовано в `01`, за двумя исключениями, помеченными ниже).

1. `release_year` заменяется на `release_decade` (бины `<1990`, `1990–1999`, `2000–2009`, `2010–2019`, `2020+`) плюс бинарный `is_recent_release` (год >= 2019).
2. `age_rating` кодируется порядковым `age_rating_ord`: {0→0, 6→1, 12→2, 16→3, 18→4, 21→5}.
3. Мультилейбловые поля (жанры, страны, актёры, режиссёры) превращаются в скалярные скоры по схеме Top-N с логарифмическим затуханием веса `1 / log2(rank + 1)`: Top-20 для жанров и стран, Top-50 для актёров и режиссёров.
4. Добавляется бинарный `is_kids_genre` (наличие жанра «для детей»); исходный `for_kids` из признакового пространства исключается.
5. `studios` исключается полностью.
6. Логарифмируются счётчики: `item_popularity_log`, `item_avg_duration_log`, `user_total_interactions_log`, `user_avg_duration_log`. Для полноты хранятся и нелогированные версии `user_total_interactions`, `user_avg_duration`.
7. Пропуски в `age`, `sex`, `income` заполняются значением `Unknown`.
8. Кросс-признак `is_kids_user_and_kids_content` = 1, если `kids_flg == 1` и `age_rating_ord <= 1`.

Отклонения от первоначального плана:

- Признаки `user_total_movies`, `user_total_series`, `user_series_ratio` планировались, но в финальный код `01` не вошли: при медиане истории в 2 взаимодействия различение «фильм vs сериал» на пользователя даёт слишком много нулей и почти не несёт сигнала.
- `for_kids` исключён из основного FE (из-за 96% пропусков), но в контрольной модели `04` используется как сырой признак.

**Ключевые выводы:**
- Основное ограничение данных — экстремальный холодный старт: 58% тестовых пользователей не встречались в train, медиана истории 2 взаимодействия.
- 14-дневные окна валидации и теста — компромисс между сглаживанием недельной сезонности и свежестью данных.
- Свежесть контента и логарифмирование популярности важны: сырые популярности имеют длинный хвост (медиана 11, максимум 142 167).
- Естественная схема FE — категориальное кодирование + Top-N с затуханием для мультилейбловых полей + логарифмированные агрегаты по юзеру и айтему + один кросс-признак.

## 3. Построение бейслайна

В качестве бейслайна можно было взять рекомендацию топ-10 популярного контента для всех или CatBoost на сырых признаках, но это плохо отражает цель исследования — проверить, конкурируют ли обучаемые представления именно с сильным ручным FE. Поэтому baseline построен как двухэтапная схема с содержательным набором признаков.

### 3.1. Ручные признаки (20 штук)

Категориальные: `content_type`, `release_decade`, `age`, `sex`, `income`.
Пользовательские числовые: `kids_flg`, `user_total_interactions`, `user_total_interactions_log`, `user_avg_duration`, `user_avg_duration_log`.
Признаки айтема: `age_rating_ord`, `is_recent_release`, `is_kids_genre`, `item_popularity_log`, `item_avg_duration_log`, `genre_score`, `country_score`, `actor_score`, `director_score`.
Кросс: `is_kids_user_and_kids_content`.

Важность признаков, обученного CatBoost (выгрузка `get_feature_importance`):

| Признак | Важность, % |
|---|---|
| `item_popularity_log` | 59.96 |
| `item_avg_duration_log` | 16.46 |
| `user_total_interactions` | 6.96 |
| `user_total_interactions_log` | 6.04 |
| `user_avg_duration` | 3.20 |
| `user_avg_duration_log` | 2.82 |
| `kids_flg` | 1.88 |
| `age_rating_ord` | 0.83 |
| Остальные | < 0.5 |

Два признака (`item_popularity_log`, `item_avg_duration_log`) в сумме дают 76% важности. Это создаёт ключевое ограничение для альтернативных подходов: любая модель, которая откажется от этих агрегатов в пользу эмбеддингов, должна их чем-то заменить.

### 3.2. Rетривер (KNN + Popular)

Прямое ранжирование 840К пользователей на 16К айтемов вычислительно неэффективно и особенно нестабильно для холодных пользователей. Поэтому для каждого пользователя формируется пул из ~500 кандидатов.

Строится разреженная матрица признаков айтемов `MultiLabelBinarizer`: жанры, страны с весом 1.0, актёры, режиссёры с весом 0.5. Итоговая матрица — 15 963 × 70 907 (CSR).

- Холодные пользователи (история < 5 или отсутствует): пул = топ-500 популярных тайтлов train.
- Тёплые пользователи: top-250 ближайших по усреднённой косинусной близости к истории + топ-500 популярных, дедупликация, удаление уже просмотренных, обрезка до 500.

Такая схема обеспечивает баланс персонализации и покрытия холодной зоны.

### 3.3. Негативное семплирование и сборка train_final

Для каждой позитивной пары (user, item) генерируются 2 негативные: случайная пара вне истории пользователя. Генерация векторизована чанками с фильтрацией через множество позитивов. Итог: 3 059 544 позитива + 6 119 088 негативов = **9 178 632** примера в `train_final` (столбец `target` — 1/0).

### 3.4. Гиперпараметры CatBoost

### 3.6. Сравнение с CatBoost без ручных признаков (04)

Для контроля обучили CatBoost на 8 сырых признаках: `content_type`, `age`, `sex`, `income`, `kids_flg`, `release_year`, `age_rating`, `for_kids`. Внутренний Logloss = 0.4805 (против 0.1767 у baseline). Метрики:

| Метрика | Train | Val | Test |
|---|---|---|---|
| HR@10 | 0.2940 | 0.3300 | 0.2420 |
| NDCG@10 | 0.1777 | 0.1637 | 0.1095 |
| MAP@10 | 0.1468 | 0.1266 | 0.0815 |

Разрыв по MAP@10 на val — +0.035 в пользу полного FE; на test — +0.033. Это подтверждает, что основной вклад в качество даёт именно feature engineering, а не выбор алгоритма.

**Ключевые выводы:**
- Baseline на ручном FE — сильный: MAP@10 = 0.162 (val) / 0.115 (test), Gap(train-val) < 0.02, переобучения нет.
- 76% важности приходится на два агрегата — `item_popularity_log` и `item_avg_duration_log`. Любая альтернативная модель должна их либо сохранить, либо чем-то заменить.
- Отказ от FE (модель 04) снижает MAP@10 на val на 0.035 и на test на 0.033: без ручных признаков даже сильный бустинг проседает.
- Разбивка cold/warm показывает разные профили: на val warm-пользователи предсказываются лучше, на test профиль инвертируется, что связано с распределением активности в пиковый августовский период.

## 4. Двубашенная модель

KNN широко применяется в рекомендательных системах, включая нашу схему retrieval. Возникает естественная гипотеза: если вместо фиксированной косинусной близости обучить нейросетевые энкодеры, которые сами проецируют пользователей и айтемы в общее векторное пространство, модель сможет выучить более подходящую метрику близости. Это идея контрастивного обучения, в рекомендательных системах известная как Two-Tower.

Есть серьёзное опасение: в данных 58% test-пользователей — холодные, а у остальных медиана истории — 2 взаимодействия. Сырых демографических и контентных признаков может не хватить, чтобы башни выучили осмысленное пространство. Эксперимент проведён, чтобы проверить это напрямую.

### 4.1. Архитектура

- **User Tower**: Embedding(age, 16) + Embedding(sex, 8) + Embedding(income, 16) + скаляры `kids_flg`, `user_total_interactions_log` -> Linear(128) -> ReLU -> Dropout(0.2) -> Linear(64) -> ReLU. Выход: 64-мерный вектор.
- **Item Tower**: Embedding(content_type, 16) + Embedding(release_decade, 16) + 8 числовых признаков (`age_rating_ord`, `genre_score`, `country_score`, `actor_score`, `director_score`, `item_popularity_log`, `item_avg_duration_log`, `is_kids_user_and_kids_content`) -> Linear(128) -> ReLU -> Dropout(0.2) -> Linear(64) -> ReLU.
- **Projection Head**: 64 -> 32 -> 32 для обеих башен (для лосса используются проекции).
- **Loss**: InfoNCE с in-batch negatives, `temperature = 0.1`. Общий размер — 33 944 параметра.
- **Обучение**: 10 эпох, `AdamW(lr=1e-3, weight_decay=1e-4)`, `CosineAnnealingLR`, `batch_size=512`, `grad_clip=1.0`. Около 85 с на эпоху, итого ~14 минут на T4.

### 4.2. Результаты

Loss:

```
epoch 1/10  | train 6.1061 | val 6.0828
epoch 5/10  | train 6.0817 | val 6.0969
epoch 10/10 | train 6.0732 | val 6.1190
```

За 10 эпох train loss снизился на 0.03, val loss вырос. Модель фактически не обучалась.

Метрики в финальной оценке (`06`):

| Метрика | Train | Val | Test |
|---|---|---|---|
| HR@10 | 0.2440 | 0.2140 | 0.1940 |
| NDCG@10 | 0.1159 | 0.0864 | 0.0673 |
| MAP@10 | 0.0788 | 0.0565 | 0.0411 |

На val MAP@10 = 0.0565 — в 2.9 раза ниже baseline (0.1617). На cold-подгруппе val (N=120): HR 0.183 / NDCG 0.067 / MAP 0.040. На warm (N=380): HR 0.224 / NDCG 0.093 / MAP 0.062. На test: cold (386) — HR 0.238 / NDCG 0.085 / MAP 0.053; warm (114) — HR 0.044 / NDCG 0.006 / MAP 0.002.

### 4.3. Почему лосс не двигался

1. **Ограниченность сигнала в сырых признаках**. Пара user-item описывается парой разреженных векторов: с одной стороны — 3 категориальных демографических признака (кардинальности 7, 3, 7) и скаляр числа взаимодействий; с другой — тип контента, десятилетие и 8 числовых скоров. Условная энтропия «какой айтем выберет пользователь с такими признаками» слишком высока: почти все пары (u, i) равновероятны, и InfoNCE не имеет градиентного сигнала, который позволил бы сдвинуть эмбеддинги.

2. **Малая ёмкость**. 33К параметров против сотен деревьев CatBoost, которые последовательно дробят пространство признаков. Проекционная голова 64 -> 32 -> 32 не в состоянии выразить такие нелинейные взаимодействия, как «пользователь 35–44 с детьми, предпочитающий советское кино», через 64-мерное пространство с контрастивным лоссом.

3. **In-batch negatives без аугментаций**. В отличие от vision/NLP, где применяются сильные аугментации (crop, flip, dropout на токенах), здесь нет способа «испортить» положительную пару, не потеряв её семантику. Без аугментаций in-batch negatives слишком простые, и модель быстро скатывается в тривиальное решение: все эмбеддинги близки друг к другу.

4. **Холодный старт**. У 71% пользователей train истории меньше 5 взаимодействий. В User Tower попадают только демографические признаки — они не различают пользователей с одинаковым возрастом, полом и доходом, которых много. Модель не имеет возможности персонализировать представление даже для позитивов.

Всё это соответствует исходному предположению: контрастивное обучение на сырых признаках в условиях экстремального холодного старта не работает.

**Ключевые выводы:**
- Двубашенная модель с InfoNCE не обучилась: loss за 10 эпох почти не менялся, MAP@10 на val = 0.0565 — в 2.9 раза хуже baseline.
- Основные причины: высокая условная энтропия сырых признаков, малая ёмкость, отсутствие аугментаций, доминирование холодных пользователей.
- Подтверждён исходный риск: 58% test-пользователей и 71% train-пользователей с историей <5 делают контрастивный подход плохо применимым к задаче.

## 5. VAE

Альтернативное направление: не учить модель «сближать» пользователей и айтемы, а обучить её лучше сжимать и понимать сами данные. Если VAE научится извлекать скрытые латентные признаки, это даст три выигрыша:

- Уменьшится потребность в ручном FE.
- Возможно улучшение метрик, поскольку CatBoost хуже работает с очень широкими разреженными пространствами признаков; компактные нелинейные эмбеддинги могут оказаться эффективнее.
- Снизятся затраты на хранение и инференс — вместо длинных векторов передаются 8-мерные представления.

### 5.1. Архитектура

Гибридный VAE обучается на позитивных парах (только `target=1`). Внутри — две независимые ветки с общим лоссом:

- **User VAE**: Encoder(Emb(age, 16) + Emb(sex, 8) + Emb(income, 16) + `kids_flg`) -> `fc_mu: Linear(41->8)`, `fc_logvar: Linear(41->8)`. Декодер: Linear(8->64) -> ReLU -> Dropout(0.2) -> Linear(64->41) -> разбиение на 4 головы реконструкции (`out_age`, `out_sex`, `out_income`, `out_kids`).
- **Item VAE**: Encoder(Emb(content_type, 16) + Emb(release_decade, 16) + `age_rating_ord`) -> `fc_mu: Linear(33->8)`, `fc_logvar: Linear(33->8)`. Декодер: Linear(8->64) -> ReLU -> Dropout(0.2) -> Linear(64->33) -> 3 головы (`out_type`, `out_decade`, `out_age_rating`).

Общее число параметров — 8 025.

**Loss**:

- Reconstruction: CE для age/sex/income/content_type/release_decade, BCE для `kids_flg`, MSE для `age_rating_ord`.
- KL-дивергенция по обеим ветвям с весом 0.1.
- Denoising: 15% входных токенов случайно заменяются случайными значениями из словаря (реализовано через `torch.where`).

**Обучение**: 15 эпох, `AdamW(lr=5e-3, weight_decay=1e-3)`, `CosineAnnealingLR`, `batch_size=512`, `grad_clip=1.0`. Около 64 с на эпоху, итого ~16 минут на T4.

### 5.2. Динамика обучения

```
epoch 1/15  | total 7.8800 | recon 7.6831 | kl 1.9688
epoch 5/15  | total 7.6601 | recon 7.6597 | kl 0.0037
epoch 10/15 | total 7.6592 | recon 7.6592 | kl 0.0002
epoch 15/15 | total 7.6589 | recon 7.6589 | kl 0.0000
```

Reconstruction стабилизировался на 7.6589. KL-дивергенция упала до 0.0000 уже к 13-й эпохе — posterior collapse. Модель выродилась в детерминированный автоэнкодер: латентное пространство несёт информацию только через mu, шум почти отсутствует. Для табличных данных с низкой кардинальностью категориальных признаков (7 значений для age, 3 для sex) это типичный исход: декодер слишком мощный, стимула у регуляризатора нет.

### 5.3. Признаки для CatBoost (28 штук)

Из обученного VAE извлекаются 8-мерные `user_z` и `item_z`. Финальный набор признаков для CatBoost:

- Категориальные: `age`, `sex`, `income`, `content_type`, `release_decade`.
- Пользовательские: `kids_flg`, `user_total_interactions_log`, `user_avg_duration_log`, `user_emb_0..7`.
- Айтема: `age_rating_ord`, `is_recent_release`, `is_kids_genre`, `item_emb_0..7`.
- Кросс: `is_kids_user_and_kids_content`.

Важно: в этом наборе отсутствуют `item_popularity_log`, `item_avg_duration_log`, `genre_score`, `country_score`, `actor_score`, `director_score`, а также нелогированные `user_total_interactions`, `user_avg_duration`. То есть выпали два признака, которые в baseline 02 давали 76% важности.

### 5.4. Метрики CatBoost на VAE-эмбеддингах

Logloss (внутренний val) = 0.2988 против 0.1767 у baseline. Best iteration = 499. Обучение ~5.5 мин.

| Метрика | Train | Val | Test |
|---|---|---|---|
| HR@10 | 0.4180 | 0.4520 | 0.3740 |
| NDCG@10 | 0.1995 | 0.1762 | 0.1350 |
| MAP@10 | 0.1397 | 0.1124 | 0.0834 |

Разбивка по cold/warm:
- val cold (120): HR 0.3750 / NDCG 0.1306 / MAP 0.0783; warm (380): HR 0.4763 / NDCG 0.1907 / MAP 0.1232.
- test cold (386): HR 0.4145 / NDCG 0.1526 / MAP 0.0949; warm (114): HR 0.2368 / NDCG 0.0754 / MAP 0.0445.

### 5.5. Сравнение с baseline

| Метрика | 02 baseline (val) | 05 VAE (val) | Δ |
|---|---|---|---|
| HR@10 | 0.4560 | 0.4520 | -0.004 |
| NDCG@10 | 0.2177 | 0.1762 | -0.042 |
| MAP@10 | 0.1617 | 0.1124 | -0.049 |

| Метрика | 02 baseline (test) | 05 VAE (test) | Δ |
|---|---|---|---|
| HR@10 | 0.3820 | 0.3740 | -0.008 |
| NDCG@10 | 0.1641 | 0.1350 | -0.029 |
| MAP@10 | 0.1146 | 0.0834 | -0.031 |

По Hit Rate@10 результат сопоставим с baseline: 0.4520 против 0.4560 на val, 0.3740 против 0.3820 на test. То есть модель находит релевантный тайтл в топ-10 почти так же часто, как baseline. По метрикам ранжирования (NDCG@10, MAP@10) отставание значительное: NDCG@10 −0.042 на val, MAP@10 −0.049 на val. Релевантные тайтлы попадают в топ-10, но оказываются ниже в нём.

Причина такого расхождения — урезанный набор признаков: из финальной схемы 05 удалены `item_popularity_log` и `item_avg_duration_log` (76% важности в baseline), а также ранговые веса жанров/стран/актёров/режиссёров. VAE-эмбеддинги эти признаки не компенсируют.

### 5.6. Пути улучшения

Чтобы разница с baseline стала значимой в плюс, а не в минус, нужны следующие изменения.

1. **Вернуть `item_popularity_log` и `item_avg_duration_log`** в набор признаков для CatBoost на VAE-эмбеддингах. Это перестанет быть чистым экспериментом «VAE vs ручной FE», но позволит проверить, дают ли VAE-эмбеддинги прирост **поверх** сильных агрегатов, а не вместо них. Ожидаемо это должно почти дотянуть VAE-вариант до baseline и дать шанс на положительный прирост.

2. **β-VAE или VQ-VAE**. Классический VAE с KL-коллапсом не использует латентное пространство. β-VAE с большим коэффициентом KL или VQ-VAE с дискретным латентным слоем заставляют модель использовать скрытые переменные и не терять информацию на реконструкции.

3. **Более широкий bottleneck и несколько голов**. 8-мерный латентный слой слишком узкий: он сжимает 41 исходный признак в 8 значений. 16–32 измерения с более разнообразными декодерами могут дать более информативное представление.

4. **Supervised VAE**. Использовать лейбл позитива при обучении VAE: decoder предсказывает не только исходные признаки, но и `target`. Это вносит в латентное пространство сигнал о релевантности.

5. **Использовать VAE-эмбеддинги в retrieval, а не как фичи для CatBoost**. Компактные 8-мерные представления можно применить как метрику близости для KNN-ретривера вместо или вместе с ручной Multi-Hot матрицей. Это может улучшить качество кандидатов, а не только ранжирование.

**Ключевые выводы:**
- VAE успешно обучился на уровне реконструкции (recon loss стабильно 7.659), но латентное пространство деградировало (KL→0): posterior collapse.
- CatBoost на VAE-эмбеддингах **проигрывает** baseline по MAP@10 на 0.049 (val) и 0.031 (test), хотя Hit Rate@10 почти совпадает.
- Основная причина отставания — не свойство VAE-эмбеддингов как таковых, а урезанный набор признаков: из схемы 05 исключены два агрегата, которые в baseline дают 76% важности.
- При возврате этих признаков, а также при замене классического VAE на β-VAE/VQ-VAE или supervised-вариант, есть основания ожидать не отрицательного, а нулевого или положительного прироста.

### 6.1. Сводное сравнение моделей

Все модели оценивались на одном и том же пуле кандидатов и одном и том же стратифицированном семпле из 500 пользователей на каждом сплите. Метрики — средние по пользователям, K = 10.

**Validation:**

| 04 catboost raw | 8 сырых | 0.3300 | 0.1637 | 0.1266 |
| 05 VAE + catboost | 28 (VAE + subset ручных) | 0.4520 | 0.1762 | 0.1124 |
| 03 two-tower | эмбеддинги, dot-product | 0.2140 | 0.0864 | 0.0565 |

**Test:**

| 05 VAE + catboost | 0.3740 | 0.1350 | 0.0834 |

### 6.2. Основные результаты

1. **Baseline на ручном FE** — самая сильная модель по всем метрикам кроме одного случая (cold HR на test, где VAE незначительно опережает baseline). Это подтверждает, что в условиях экстремального холодного старта качественный feature engineering даёт основной вклад в качество.

2. **Отказ от ручных признаков (модель 04)** приводит к падению MAP@10 на 0.035 (val) и 0.033 (test). Даже CatBoost без FE существенно слабее.

3. **Двубашенная модель не работает** в этом датасете: loss стагнирует, MAP@10 в 2.9 раза хуже baseline. Основные причины — высокая условная энтропия сырых признаков и доминирование холодных пользователей.

4. **VAE** успешно сжимает признаки и восстанавливает вход, но posterior collapse обесценивает латентное пространство. На урезанном наборе признаков (без популярности и длительности) CatBoost на VAE-эмбеддингах проигрывает baseline: MAP@10 −0.049 на val, −0.031 на test. Hit Rate@10 при этом сопоставим (0.452 vs 0.456 на val), что означает: модель находит релевантные тайтлы, но хуже их ранжирует.

5. **Инверсия cold/warm на test**. На val тёплые пользователи предсказываются лучше холодных, на test — наоборот. Это объясняется пиковой августовской активностью в test: у тёплых пользователей к этому периоду более широкий и разнородный профиль, тогда как холодные лучше попадают в топ популярного. На стабильность модели в проде это влияет слабо, но подчёркивает ограниченность семпла в 500 пользователей для оценки поведения отдельных сегментов.

### 6.3. Ответ на исследовательский вопрос

Задание ставит вопрос: можно ли автоматизировать построение признаков или заменить их обучаемыми представлениями без потери качества.

**Полная замена ручных признаков — нет.** В экстремальном cold-start (58.19% test-пользователей отсутствуют в train, 71.4% train-пользователей с историей <5, медиана истории 2) CatBoost на ручном FE даёт MAP@10 = 0.1617 на val и 0.1146 на test. Сырые признаки без FE дают 0.1266 / 0.0815, VAE-эмбеддинги без сильных ручных агрегатов — 0.1124 / 0.0834. Ни одна из автоматических альтернатив не достигает уровня baseline.

**Гибридная схема в текущей реализации — нет.** Смешение VAE-эмбеддингов с subset ручных признаков (без `item_popularity_log` и `item_avg_duration_log`) дало ухудшение относительно полного ручного набора: −0.049 MAP@10 на val, −0.031 на test.

**Что подтвердилось положительно** — сама двухэтапная схема с KNN-ретривером и CatBoost-ранкером на ручных признаках. Gap(train-val) < 0.02, метрики стабильны, ранжирование работает.

**Научный вклад работы.**

1. На воспроизводимом пайплайне (фиксированные split, кандидаты, семпл) показано, что в условиях KION (низкая кардинальность категориальных признаков, короткая история, длинный хвост популярности) ни контрастивное обучение (Two-Tower), ни VAE при выбранных гиперпараметрах не дают прироста над ручным FE.

2. Отдельно выделен эффект доминирования `item_popularity_log` и `item_avg_duration_log` в важности признаков. Любой подход, который отказывается от этих агрегатов в пользу компактных эмбеддингов, должен обеспечить сравнимую или превосходящую замену — иначе проигрыш по метрикам предсказуем. VAE в текущей конфигурации такой замены не даёт.

3. Практическая рекомендация для аналогичных задач: приоритет — (а) ручные агрегаты (популярность, средняя длительность, ранговые веса категориальных признаков), (б) категориальное кодирование через CatBoost, (в) retrieval через KNN-по-контенту + Popular. Обучаемые представления стоит рассматривать как дополнение, а не замену, и проверять их на полном наборе ручных признаков, а не на урезанном.

### 6.4. Ограничения и направления развития

**Ограничения работы.**

- В финальной схеме VAE-варианта намеренно убраны `item_popularity_log` и `item_avg_duration_log` — это ухудшило сравнимость с baseline. Честное сравнение «VAE + полный FE vs полный FE без VAE» не было проведено и является очевидным следующим шагом.
- Экспериментальная ветка «Hybrid VAE с контрастивным лоссом» (реконструкция + InfoNCE + KL) описана как неудачная, но её код и логи в текущий набор не вошли; это стоит оформить отдельно.
- Семпл в 500 пользователей на каждом сплите даёт шум: cold/warm разбивка по 114 тёплым на test слишком мала для уверенных выводов по сегментам.
- Гиперпараметры VAE (β = 0.1, latent = 8, only reconstruction loss) подобраны быстро; β-VAE и supervised VAE не тестировались.

**Направления развития.**

- **β-VAE / VQ-VAE / supervised VAE**: попытки побороть posterior collapse. Особенно перспективно добавить в декодер голову на `target`, чтобы латентное пространство учитывало релевантность.
- **Контрастивное обучение с аугментациями**: маскирование отдельных категориальных признаков, дропаут истории просмотров; обучение не на сырых признаках, а на сжатых VAE-эмбеддингах в качестве входа для Two-Tower.
- **Sequence-based модели для тёплых пользователей**: SASRec/BERT4Rec на последовательностях истории. В cold-start не помогут, но могут улучшить ранжирование для 29% тёплых пользователей и снизить разрыв с baseline.
- **Гибридный двухступенчатый ранкер**: для cold — текущий baseline, для warm — sequence model; ансамбль через stacking.
- **Автоматизация FE через агент**: генерация SQL-подобных признаков и автоматический отбор по приросту на валидации. Учитывая, что лучший результат дают простые агрегаты, есть пространство для поиска по окнам, типам агрегации и сочетаниям полей.
- **Учесть типы событий и временные окна**: в текущем датасете только просмотры. На Yambda (показы, клики, лайки) можно построить конверсионные признаки показ→клик, что может дать больший прирост, чем нейросетевые эмбеддинги.

**Ключевые выводы:**
- Итоговый лидер — CatBoost на полном наборе ручных признаков (val MAP@10 = 0.1617, test 0.1146). Все альтернативные подходы в текущей реализации проигрывают.
- Полная замена ручных признаков обучаемыми представлениями в этом датасете невозможна: причины — холодный старт, короткая история, доминирование агрегатов популярности.
- Наиболее перспективные направления — не полная замена, а гибрид: VAE-эмбеддинги **поверх** полного FE, либо sequence-модели для warm-сегмента.
- Для автоматизации FE логично двигаться в сторону поиска и отбора SQL-подобных агрегатов, а не в сторону end-to-end нейросетевых решений.
